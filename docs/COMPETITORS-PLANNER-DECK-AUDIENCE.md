### What people complain about, and the answer

| Complaint (rival)                                                                         | Lumora's answer                                                                                                   |
| ----------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------- |
| Rigid structure, little customizing, dated look (Rundown Creator)                         | Extra columns, colors, floated cues, per-person column views, a quiet modern sheet.                               |
| No scripting: scripts live in another app (Rundown Studio)                                | Scripts per cue, read-time, a prompter that follows the show, and the scripts load into Lumora's prompter.        |
| Prices per seat or per event climb fast for a crew (Rundown Studio, Shoflo/LASSO, Cuez)   | Everyone on the plan is included; viewers and the public link cost nothing extra.                                 |
| Steep learning curve, broadcast jargon (Cuez, Rundown Creator)                            | Plain words ("Run the show", "GO · next cue", "Float this cue"); templates to start from.                         |
| A timer, not a plan: little detail per cue, caps on connections and messages (Stagetimer) | The timer is part of the plan: notes, scripts, crew, tasks; no caps on viewers or messages.                       |
| Sheets do the math by hand and can't run a show (Google Sheets / Notion)                  | Times, totals and drift are automatic; live mode, timers and crew phones come with it; sheets import in one step. |
| Built for weekly services, not productions (Planning Center)                              | Built for productions: switcher cues, call sheets, gear, budget, stage timer.                                     |
| One show needs five tools: rundown, timer, call sheets, file share, chat                  | One place, and it drives the switcher itself.                                                                     |

### Lumora only

- The plan follows Lumora's run of show: cues run in the switcher move the
  crew's phones, the stage timer and the prompter.
- Rehearsal times become the plan's lengths in one click.
- Scripts load into the switcher's prompter from the plan.
- Budget, gear, tasks, crew calls, chat and the run of show in one shared plan,
  with a call sheet printed from it.
- Personal calendar feed of every plan you are on.

### Left, and why

- **Email notifications**: Supabase has no free outgoing email for app
  messages; it needs a mail provider (Resend, Postmark…) and an Edge Function
  with its key. Mentions and tasks notify in the Planner and the browser now.
- **Open API**: the public link's data is readable as JSON
  (`rpc/planner_public`), but there is no documented API or webhooks yet.
- **Offline editing**: the installed Planner opens every recent plan without
  internet, read-only (lists included). Editing offline needs a sync queue and
  conflict handling; not started, to keep "last write wins per cue" reliable.
- **Timer screen designer**: not started.
- **Calendar feeds** depend on Supabase answering `text/calendar` for the
  `planner_ical` functions (PostgREST media type handlers) and accepting the
  key in the address; check once after running update 10 (see the report).

### Built in this round

- **Q&A**: phones vote questions up (once each, and can take the vote back);
  the list on the phones puts the most wanted first and answered ones last.
  "Hold new questions until I approve them" keeps every new question off the
  phones until the operator approves it (`POST /api/ask/vote`).
- **Word cloud**: a poll kind; up to three words or short phrases from each
  phone, counted whatever their letter case, the most sent drawn biggest;
  the operator can take any word out (`POST /api/word`).
- **Rating**: a poll kind; one to five stars, the average and how the stars
  were given on screen, with an optional comment that only the operator sees.
- **Reactions**: Love, Haha, Wow and Yes, tapped on phones, gathered by the
  app's server four times a second so a crowd never floods the show, rising
  over the picture as flat badges (`POST /api/react`).
- **Export**: each poll, word cloud, rating and trivia game, and the
  questions, save as a CSV that opens in Excel, Numbers or Google Sheets
  (cells that would run as formulas are kept as text).
- **Control**: the control API's `voting`, `questions` and `reactions`
  commands, in Companion too.
